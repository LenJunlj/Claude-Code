# 汽车测试用例设计方法论

本文总结汽车软件（车载控制器）测试用例设计的系统方法论，涵盖设计流程、功能属性分类、方法选择策略和评审标准。

## 核心设计流程

```
理解需求 → 设计测试用例 → 评审测试用例
```

理解需求是前提，设计是核心，评审是质量保障。

## 5 步设计策略

### 步骤 1：分析功能需求
将功能需求拆解成**最小的可测单元**——明确的输入和单一的输出结果。避免"一个输入，多个输出"，需拆分到 **一个输入 → 一个明确输出**。

### 步骤 2：确定功能属性（7 类）
根据功能特征将需求归入以下类别，每类有推荐的设计方法：

| 功能属性 | 推荐方法 | 示例 |
|----------|----------|------|
| **阈值类** | 边界值、等价类 | 车速 > 60 且 < 120 → 定速巡航 |
| **查表类** | 边界值、等价类 | 扭矩根据车速+油门踏板查表 |
| **条件使能类** | 边界值、等价类、MCDC | 条件1&条件2&条件3 → 功能A |
| **配置类** | 等价类 | 写/不写配置字 |
| **状态跳转类** | 状态转换、等价类、边界、MCDC、路径覆盖 | IGON/Init/KLACC 状态切换 |
| **故障类** | 等价类 | 触发故障 → 恢复 → 功能恢复 |
| **流程类** | 基本路径、边界值、等价类、场景分析 | 高压上下电流程 |

### 步骤 3：选择设计方法

详见 [[test-case-design-methods|测试用例设计方法体系]]。

### 步骤 4：按模板编制测试用例

参考 [[../templates/汽车测试用例设计模板|汽车测试用例设计模板]]。

### 步骤 5：经验/错误推导补充
站在开发者角度查漏补缺，是测试工程师能力的分水岭。

## 设计资源基础

| 测试阶段 | 参考文档 |

| **HIL**（硬件在环） | 控制器标准规范、功能规范、硬件规格书、CAN矩阵、诊断信息表 |
| **MIL**（模型在环） | 软件需求说明书、软件详细设计、软件架构设计 |
| **补充** | 质量问题管理表、测试经验知识库 |

## 评审要点

1. 是否覆盖所有需求点（双向追溯性）
2. 用例数量是否达到覆盖度要求
3. 每个用例步骤 ≤ 10 Step
4. 是否选择了对应的设计方法（设计依据）
5. 编号规则是否统一
6. 功能安全用例是否遵循安全标准
7. 是否可执行（前提、步骤、数据、预期清晰）
8. 是否包含正常和异常用例
9. 是否按模板编写
