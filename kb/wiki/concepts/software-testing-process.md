# 软件测试流程

软件测试流程（Software Testing Process）是规范化的测试活动序列，从计划到结束覆盖测试全生命周期，确保测试的系统性和可追溯性。

## 流程阶段

### 1. 测试计划 — 5W1H

测试计划阶段明确测试的整体策略和资源安排，通过 **5W1H** 框架定义：

| 维度 | 内容 | 说明 |
|------|------|------|
| **What** | 测什么 | 测试范围、功能模块 |
| **Who** | 谁来测 | 测试人员分工 |
| **Where** | 在哪里测 | 测试环境（硬件、软件、网络） |
| **When** | 什么时候测 | 测试时间节点、里程碑 |
| **Why** | 为什么测 | 测试目标、风险分析 |
| **How** | 怎么测 | 测试方法、工具、策略 |

### 2. 测试监督与控制

由 **测试经理（TM，Test Manager）** 负责，贯穿整个测试过程：
- **进度监督**：跟踪测试任务完成情况，确保按计划推进
- **质量监督**：评估测试效果，把控缺陷收敛趋势
- **风险控制**：识别和应对测试过程中的风险

### 3. 测试分析

分析"测什么问题"，是将测试需求转化为可操作测试条件的过程。

- **输入**：需求文档、设计文档
- **输出**：**测试条件**（Test Conditions）—— 即测试用例的标题级描述
- **关键要求**：**可追溯性**（Traceability）—— 每个测试条件必须可追溯到原始需求，确保需求覆盖无遗漏

### 4. 测试设计

对测试条件的细化，将抽象的测试条件展开为具体可执行的测试步骤。

- **输入**：测试条件
- **输出**：**测试用例**（Test Cases）—— 包含前置条件、输入数据、执行步骤、预期结果

### 5. 测试实施

将测试用例转化为可执行的测试规程，为测试执行做准备。

- **环境搭建**：部署被测系统、配置测试环境
- **用例分组**：按功能模块、优先级、测试类型等维度组织用例
- **优先级设定**：确定用例执行的先后顺序（如 P0/P1/P2）
- **输出**：**测试规程**（Test Procedures）—— 测试用例的执行顺序和编排

### 6. 测试执行

实际开展测试，运行测试用例并记录结果。

- **输出**：
  - **Bug单/缺陷报告** —— 记录发现的缺陷
  - **测试日志** —— 记录执行过程和数据
  - **检查表** （Checklist）—— 验证关键检查点

### 7. 测试结束

对标测试计划，评估测试是否完成，总结经验教训。

- **输入**：测试计划、测试结果、缺陷数据
- **输出**：
  - **测试报告** —— 测试结果汇总、质量评估、版本建议
  - **经验总结** —— 过程改进建议、最佳实践沉淀

## 流程图

```
测试计划 → 测试监督与控制（贯穿全程）
    ↓
测试分析 → 输出：测试条件（可追溯）
    ↓
测试设计 → 输出：测试用例
    ↓
测试实施 → 输出：测试规程（环境+分组+优先级）
    ↓
测试执行 → 输出：Bug单、测试日志、检查表
    ↓
测试结束 → 输出：测试报告、经验总结
```

## 关键原则

- **可追溯性**（Traceability）：每个测试条件 ↔ 原始需求，确保全覆盖
- **渐进细化**：从计划 → 分析 → 设计 → 实施，逐步从抽象到具体
- **监督闭环**：TM 全程监控，确保进度和质量可控
- **经验复用**：测试结束后的经验总结反哺下一轮测试
