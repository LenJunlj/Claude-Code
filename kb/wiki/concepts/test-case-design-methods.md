# 测试用例设计方法体系

本文系统整理测试用例设计方法，按 [[iso-29119-4|ISO/IEC/IEEE 29119-4:2015]] 三大分类组织：**基于规格说明**、**基于结构**、**基于经验**。

---

## 一、基于规格说明（黑盒）方法

基于功能需求/规格说明设计用例，不关注内部结构。

### 边界值分析（BVA）⭐
在等价类边界上选取测试值——最小值、最大值、略超边界等。

> **适用**：阈值类、查表类、条件使能类
> **汽车示例**：车速 > 60 且 < 120 进入定速巡航 → 测试 59、60、61、119、120、121

### 等价类划分 ⭐
将输入域划分为有效/无效等价类，每类取一个代表值。

> **适用**：阈值类、查表类、配置类、故障类
> **汽车示例**：挡位状态 P/L/D/N/R → 每挡一个代表值 + 无效值

### 场景测试（Scenario Testing）⭐
基于用户使用场景、用例（Use Case）或操作流程设计用例。

> **适用**：流程类、系统级测试
> **汽车示例**：高压上下电完整流程测试

### 状态迁移测试（State Transition Testing）⭐
基于状态机模型，测试状态之间的转换是否合规。

> **适用**：状态跳转类
> **汽车示例**：IGON → Init → KLACC → Drive → OFF 状态切换

### 决策表测试（Decision Table Testing）
基于条件和动作的逻辑关系，覆盖所有条件组合。

> **适用**：条件使能类、多条件逻辑
> **汽车示例**：IF (车速>60 AND 巡航开关ON AND 无刹车) → 进入巡航

### 分类树方法（Classification Tree Method）
将输入域按层级分类，构建树形模型，从叶节点组合生成用例。

### 成对组合测试（Pairwise / Combinatorial）
用最少的组合覆盖所有参数对的取值组合，减少用例数量爆炸。

### 因果图（Cause-Effect Graphing）
决策表的图形化变体，分析因果关系。

---

## 二、基于结构（白盒）方法

基于代码/模型内部结构设计用例，以覆盖度为目标。

### 语句测试（Statement Testing）⭐
执行程序中的每一个可执行语句。

### 分支测试（Branch Testing）⭐
覆盖每个分支的 true/false 结果。

### 修正条件判定覆盖（MCDC）⭐
证明每个条件独立影响判定结果。功能安全项目（ISO 26262）强制要求。

> **适用**：条件使能类、安全关键功能、ASIL 等级要求

### 分支条件组合测试
覆盖判定内所有条件的取值组合。

### 数据流测试
追踪变量的定义和使用（c-use / p-use）。

---

## 三、基于经验的方法

基于测试人员的直觉、知识和经验。

### 错误猜想（Error Guessing）⭐
站在开发者角度猜测可能的错误类型并设计用例。使用缺陷检查表、错误分类法。

> **适用**：全阶段补充，高价值但依赖个人经验

---

## 按功能属性快速选型表

| 功能属性 | 推荐方法 |
|----------|----------|
| 阈值类 | 边界值 + 等价类 |
| 查表类 | 边界值 + 等价类 |
| 条件使能类 | 边界值 + 等价类 + MCDC |
| 配置类 | 等价类 |
| 状态跳转类 | 状态转换 + 等价类 + 边界 + MCDC + 路径覆盖 |
| 故障类 | 等价类 |
| 流程类 | 基本路径 + 边界值 + 等价类 + 场景分析 |
